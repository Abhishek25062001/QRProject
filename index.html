What it does

From the scan to the settled bill

Guests order from their own phone with no app and no account. Staff work the same orders from a counter screen, a kitchen display and a waiter view. Owners run the menu, the tables and the numbers from an admin panel.

Scan to order

A QR per table resolves to that restaurant's live menu. Search, categories, veg marks, item notes and a cart that survives a refresh — no download, no login.

Kitchen and counter

A live order board, a kitchen display and counter entry for walk-ins. Accepting an order prints a plain text KOT; the guest's phone sees the status change at the same moment.

Table sessions & GST billing

One party occupies one table at a time. Their orders roll into a session, the bill takes a fiscal-year number, and CGST and SGST are split per the restaurant's own tax settings.

Menu that changes mid-service

Mark a dish unavailable from the counter and every phone reading that restaurant's menu updates on the spot. Orders already placed keep their own price and name.

Tables & printable QR codes

Create tables one at a time or in bulk, download a single QR as a PNG, or print a sheet for the whole floor. Regenerating a token invalidates the old printed code immediately.

Multi-tenant by construction

The restaurant is derived from the staff member's token or from the scanned QR — never from the request body. Queries carry both the entity id and the tenant id, so one restaurant cannot read another's data.

Engineering

The parts that had to be right

A restaurant floor is a concurrency problem with cutlery. These are the decisions that keep the money and the tenancy correct when three people order from the same table at once.

  1. 01Four front ends on one API

    A customer app, a cashier/kitchen app, a restaurant admin panel and a platform console, served by one Express backend across five route groups — each with its own authentication story.

  2. 02The client never sets a price

    Order creation locks the table row, re-reads every item from PostgreSQL, rejects archived or unavailable dishes, merges duplicate lines, applies the restaurant's tax mode and writes an immutable snapshot of each line.

  3. 03Tenancy as a boundary, not a convention

    Staff requests take restaurant_id from the JWT; guest requests take it from the QR token. No endpoint accepts a tenant id from the body, and queries filter on entity id and tenant id.

  4. 04Counters allocated inside the transaction

    Per-restaurant daily order numbers and fiscal-year bill numbers are handed out under the same lock that creates the row, so a busy Saturday can't produce two order #14s.

  5. 05Realtime instead of polling

    Four room types — restaurant, menu, table and order. Staff sockets authenticate with a JWT in the handshake; guest sockets prove each order with its access token before they're allowed into that room.

  6. 06Money in integer paise

    Every subtotal, tax split and total is computed in paise and converted once at the edge, so a 5% CGST on ₹347.50 doesn't drift a rupee over a night's billing.

How the QR works

Four steps from print to payment

Every table has its own code. The code is the whole session key — there is nothing for the guest to install or remember.

  1. 1
    The owner creates a table

    The backend mints a cryptographically random, URL-safe token and builds the menu link as /m/{qrToken}. Admin downloads a PNG, or a printable sheet for the whole floor.

  2. 2
    A guest scans it

    The token resolves to a table and a restaurant. The server checks the table is active, the restaurant is live and the subscription hasn't lapsed before it returns a single menu payload.

  3. 3
    They order

    The cart posts item ids and quantities — never prices. The server locks the table, opens or joins a session, prices everything itself, and pushes order:new to the kitchen.

  4. 4
    The table settles

    Staff generate the bill from the session, take cash, card or UPI, and closing it completes the served orders and clears any open waiter requests in the same transaction.
